# Phoenix daily sales — Phase 2 preview

**No installation into the live CRM, schedule or unattended writes are enabled by this PR.** On the configured Windows PC, keep the extracted operator package together in a private folder outside the website repository. Double-click **Preview Phoenix enquiries.cmd**. On first use, enter the Netlify Project ID for l4gym.com and an expiring token from a Netlify account with the minimum necessary site access. Never paste a token into chat, a document, an email or a command line. The program only makes GET requests; this does not make the token itself read-only. Windows encrypts the token for this PC and Windows user in LocalAppData. For rotation rerun **Phoenix preview.ps1 -Setup** in PowerShell; revoke the old token in Netlify.

1. Let OneDrive finish syncing; close Excel on all devices. Run the preview. Each successful collection produces a new timestamped folder under **%LOCALAPPDATA%\Phoenix Sales\runs**. Open its **Daily actions.html** locally. Check its date. On a failure no new report or CSV is published: do not use an old report as today's queue.
2. Review overdue items first, then classification flags, first contacts, catalogue requests, quotations and qualified opportunities. A shared email can be legitimate; compare the reference and source before contacting anyone. Project size is quoted from requirements when provided, never estimated. A Netlify verified submission is not a qualified customer. Tests are excluded. The report mirrors the rehearsal; new entries are not yet in the master.
3. **After live read-only acceptance:** to import manually, close Excel, confirm sync is current on every device, then use the existing **Import Phoenix leads.cmd** and choose that run's **verified.csv**. Never replace the master with a rehearsal workbook. The Phase 1 importer checks for existing references, preserves manual records and verifies a dated backup before replacement. If a reference conflicts, investigate; do not delete a row to force the import.
4. In Website leads, classify each new record, set the owner, stage and follow-up date. Inspect drafts in the report only for confirmed Lead records; edit before manually sending from jamie@l4gym.com. Refresh the preview after CRM edits. This tool never sends messages.
5. On network, access or lock errors see **%LOCALAPPDATA%\Phoenix Sales\collection.log** (counts and categories only). A locked, offline or conflicting workbook stops the run. Rename nothing to bypass this. Local checks cannot establish whether a different PC has unsynced edits. Resolve conflicts in OneDrive and rerun. For rollback, close Excel, save a private copy of the current master, open the desired dated file under **Phoenix CRM backups** read-only and inspect it before restoring it under the original master filename. Preserve subsequent manual edits separately.
6. Reports and CSVs contain private contact information. Keep the run folders private, delete stale runs under your retention policy, and never commit them to Git. No raw IP or user agent is exported. Removing a run does not delete Netlify submissions or CRM history.

**Acceptance before activation:** preview using the real account; verify the form, reference set and values against a fresh Netlify verified CSV; repeat; test locks and conflict handling on a copy; approve the results. No scheduler is registered. A later approved Task Scheduler task could invoke the preview PowerShell script under the same Windows user without passing credentials as arguments. For unattended master writes, first implement a server-side version condition (or equivalent coordinated single-writer guarantee) and test it with two devices. A local timestamp or Excel lock file cannot guarantee this. Do not schedule the Phase 1 workbook writer.
